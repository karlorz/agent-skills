# deep-research

Source-triaged research engine with local-first evidence, grok-search freshness checks, Context7 verification, tiered model pinning, deep-fetch, content refinement, deterministic report contract, and vault integration.

**Version:** see `.claude-plugin/plugin.json` (kept in sync with `.codex-plugin/plugin.json` and root `.claude-plugin/marketplace.json`).

## When to use

- User requests comprehensive, source-triaged research on a topic across local files, documentation, repositories, and current web sources.
- Topic involves libraries, frameworks, GitHub repositories, technology comparisons, literature reviews, or architectural patterns.
- Topic involves externally mutable facts: latest versions, releases, changelogs, marketplace state, package metadata, GitHub issues/PRs, or current behavior.
- Caller requires a deterministic Status/ledger/Coverage report, multi-claim comparison, or atomic SkillWiki vault persistence.
- Periodic coverage sweeps across project repositories, announcements, and non-English ecosystems.

## When NOT to use

- Quick factual lookups or single-fact freshness questions (e.g. single latest version number or one changelog line) — prefer direct `/grok-search` or the grok-search MCP. (If deep-research is invoked anyway, it runs the full orchestrator without skipping.)
- Single-source queries where direct inspection via Context7, local files, or web search is sufficient.
- Purely local, non-freshness-sensitive tasks where ordinary file reading is enough.

## Invocation modes and flags

deep-research operates in two modes:

| Mode | How detected | Question policy | Output default |
|------|--------------|-----------------|----------------|
| `unattended` | Model/skill auto-invocation (spawned by parent agent/skill), headless / non-TTY sessions, `--unattended` flag, or prompt instruction "do not ask" | **Never asks questions** — picks recommended defaults and states assumptions in the report | **stdout / ephemeral** unless explicit `--vault` or `--save` |
| `interactive` | Attended interactive TUI session with slash command `/deep-research ...` without `--unattended` or `--ephemeral` | Asks **only** when ambiguity is strictly blocking | Vault auto-detection (vault if available, else stdout) |

### Flags

| Flag | Effect |
|------|--------|
| `--ephemeral` | Skip vault saving — print structured report to stdout only |
| `--save <path>` | Write markdown report to the specified file path |
| `--vault` | Force vault mode (errors if no vault is configured) |
| `--unattended` | Force unattended mode: zero prompts, automatic defaults, stdout default |
| `--depth <fast\|default\|thorough>` | Source plan depth (default: `default`). `fast` = minimal tagged source plan, no escalation; `default` = normal escalation; `thorough` = broad multi-source fan-out |
| `--type <concept\|comparison\|query\|entity>` | Force vault page taxonomy (vault mode only, default: `query`) |
| `--no-raw` | Skip raw source capture in vault mode |
| `--no-refine` | Skip content refinement phase |

### Output routing and vault behavior

- **Interactive default:** auto-detects vault via `skillwiki path`. If a vault exists, composes an unpublished draft and delegates transactional publication, taxonomy, index, and log updates to `skillwiki page publish` (see `references/vault-pipeline.md`). If no vault exists, prints to stdout.
- **Unattended default:** outputs directly to **stdout / ephemeral** unless `--vault` or `--save` is explicitly passed by the caller.
- **Unattended vault lock timeout:** vault lock or publication stalls hit a hard **120s timeout** and fail closed: the draft is retained and the full report is printed to stdout without spinning on the lock. Direct vault writes bypassing the publisher are never performed.

## Report contract

Reports generated by deep-research adhere to a deterministic contract validated by `scripts/lint-report.py` against `references/report-presentation-template.md`:

1. **Status header & identity block:** starts with exact `**Status: Verified**` or `**Status: Partial**`, followed immediately by a localized H1 title, evidence cutoff / verification date / scope block, and compact topic navigation (`1. ... 2. ... 3. ...`).
2. **Numbered narrative sections:** sequential plain-ASCII numbered H2s (`## 1. <title>`, `## 2. <title>`, ...) in every report language. Narrative text localizes, but ordinal numbers remain plain ASCII.
3. **Four literal audit headings:**
   - `## Freshness & Verification Status` (compact audit table for key claims, source routes, and freshness channels)
   - `## Verification Methods` (reproducible commands, checks, and canonical references)
   - `## Sources` (immutable six-column source ledger: `| Ref | Role / retained use | Publisher / title | Source type | Accessed | Exact URL or local record |`)
   - `## Coverage and uncertainty` (retained gaps classified strictly as `topic-inherent unknown`, `execution topology`, or `Evidence gap`)
4. **Evidence discipline:**
   - Pre-identifies answer-critical claims during source triage before gathering evidence.
   - Enforces claim caps: at most 6 atomic claims per question, 24 total across all questions.
   - Categorizes `source_type` as `primary`, `secondary`, `repository`, or `other`.
   - Immutable ledger: every retained external source discloses `direct-fetch` or `search-summary only`. Local evidence uses `local-record:` with repository durability. Literal role tokens remain exact English across all report languages.
   - Status semantics: `**Status: Verified**` requires every retained claim to carry non-empty external verification and zero evidence gaps. `topic-inherent unknown` is status-neutral; actual evidence gaps require `**Status: Partial**`.

For complete canonical specifications, consult `skills/deep-research/SKILL.md` and `references/report-presentation-template.md`.

## Deterministic report pipeline

deep-research employs a fail-closed candidate selection pipeline to ensure clean, structured output:

```
[Phase 3 Synthesis]
       │
       ▼
[Candidate lint (lint-report.py)] ──── pass ────► Accepted report
       │ fail
       ▼
[Structure repair (repair-report-structure.py)]
       │
       ▼
[Re-lint candidate] ───────────────── pass ────► Repaired report
       │ fail
       ▼
[Prebuilt fallback (build-fallback-report.py)]
       │
       ▼
[Fallback selection (select-report-candidate.py)] ── pass ──► Partial fallback report
       │ fail
       ▼
[Hard nonzero error (never returns malformed or empty output)]
```

- **Pre-synthesis fallback checkpoint (`scripts/build-fallback-report.py`):** before report composition, constructs a valid structured `fallback.md` checkpoint from retained claims and the source ledger. If normal synthesis fails, the prebuilt fallback provides a contract-compliant `Status: Partial` report with full audit headings and an explicit Coverage evidence gap.
- **Report linter (`scripts/lint-report.py`):** verifies heading order, H1 placement, plain ASCII ordinals, ledger columns, source citation mapping, local-record durability, temporal cutoff, status consistency, and absence of model-narrated numeric tool counts. Supports YAML frontmatter stripping and ignores vault `## Related Notes`.
- **Structure repairer (`scripts/repair-report-structure.py`):** non-destructive repair tool that fixes structural issues (H1 placement, English role tokens, `local-record:` prefixes) without altering evidence, claims, URLs, or status.
- **Candidate selector (`scripts/select-report-candidate.py`):** selects the first valid candidate in sequence (normal synthesis -> repaired -> prebuilt fallback). Exits nonzero if no candidate satisfies the report contract.

## Capability-adaptive execution

- **Subagent tiering:** When child-agent spawning is available, Phase 2 source gathering and Phase 4 content refinement spawn workers pinned to `model: "sonnet"` (or `model: "haiku"` for single-page fetches), while Phase 3 cross-source synthesis runs in the parent session context.
- **Inline execution fallback:** When child-agent spawning is unavailable, deep-research executes the exact same selected source plan sequentially inline in the parent context. This is recorded in Coverage as an informational note (`execution topology: inline fallback`) and is not an evidence gap.

## Installation

### Claude Code / Codex (Marketplace)

With the `karlorz-agent-skills` marketplace configured:

```bash
claude plugin install deep-research@karlorz-agent-skills
codex plugin add deep-research@karlorz-agent-skills --json
```

### Grok (Local development)

For local development or testing from the repository root:

```bash
grok plugin install /path/to/agent-skills/skills/deep-research --trust
```

### Invocation

Slash command:
```
/deep-research:deep-research "topic or research question" [flags]
```

Subagent invocation:
Spawnable as a subagent (pinned to `model: "sonnet"`) via `deep-research:deep-research`.

For platform-specific tool mappings and multi-agent configuration on Codex CLI/App, see `references/codex-tools.md`.
